# notice-it — 気づく仕組みチェック

対応章: [第2章 コードを読むための最低限の知識](../../../chapters/02-reading-code.md) / [第3章 設計する](../../../chapters/03-design.md) / [第6章 気づく](../../../chapters/06-noticing.md)

## 目的

意図的に壊す（[第5章](../../../chapters/05-breaking-it.md)）とは対になる、「本番で勝手に壊れた時にどう気づくか」を確認する。一番怖いのは、エラーが起きたことにすら誰も気づかない状態（[6.3節](../../../chapters/06-noticing.md#63-壊れたが誰も気づかなかったを防ぐ)）。

## 使うタイミング

- コードレビュー時、エラー処理・ログの妥当性を確認したい時
- 「なぜかこのバグに誰も気づかなかった」という事後調査の時
- 責務が混在した関数を見つけたい時

## 手順

対象コードを次の3観点で読む。

1. **エラーの握りつぶし**（[2.4節](../../../chapters/02-reading-code.md#24-エラー処理)）: `except: pass`のように例外を捕まえて何もしていない箇所、失敗時に呼び出し元へ何も伝えていない箇所を探す
2. **ログの欠落**（[6.1節](../../../chapters/06-noticing.md#61-ログ設計)）: 失敗しうる処理（外部API呼び出し・DB操作・決済など）で、失敗時に「何が」「いつ」「どんな入力で」を記録していない箇所を探す
3. **責務の混在**（[3.4節](../../../chapters/03-design.md#34-責務分離)）: 1つの関数の説明に「〜して、〜して」と「て」が2回以上出てくる関数を探す

## 出力フォーマット

```
## 気づく仕組みチェック: <対象コード名>

### エラーの握りつぶし
- `process_payment()`: except節で何も記録せずreturnしている（重大）

### ログの欠落
- `charge()`: 失敗時にログが残らない。user_id/amount/失敗理由を記録すべき

### 責務の混在
- `register_user()`: 検証・保存・通知の3責務が1関数に混在。分割を推奨
```

## やらないこと

- ログの追加・関数の分割を無断で行わない。指摘と改善案の提示までに留め、実施はユーザーの判断を待つ
