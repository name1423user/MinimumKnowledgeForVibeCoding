# ci-readiness — テストとCI/CDの整備状況チェック

対応章: [第8章 テストとCI/CD](../../../chapters/08-testing-and-cicd.md)

## 目的

テストは「毎回、誰の手も借りずに、自動で」実行され続けて初めて価値を持つ（[第8章](../../../chapters/08-testing-and-cicd.md)冒頭）。書いたテストが実際に自動実行されているか、実行され続けられる状態か（Flaky testで形骸化していないか）を確認する。

## 使うタイミング

- リリース・デプロイ前の確認
- CI設定を初めて導入する時、または見直す時
- 「テストが通ったのにバグが出た」といった事後調査

## 手順

1. **CI設定の有無を確認する**: リポジトリにCI設定ファイル（GitHub Actionsの`.github/workflows/`など）が存在するか
2. **テストピラミッドの構成を確認する**（[8.1節](../../../chapters/08-testing-and-cicd.md#81-テストピラミッド)）: 単体テスト・結合テスト・E2Eテストのファイル数・実行時間のバランスを見て、極端な偏りがないか
3. **Flaky testの兆候を確認する**（[8.4節](../../../chapters/08-testing-and-cicd.md#84-cicdが壊れかけた時のサイン)）: CI設定にリトライ処理が入っている、特定のテストが`skip`/`xfail`のまま放置されている、実行順序やシステム時刻への依存が疑われるテストがないか
4. **デプロイ前チェックリストとの接続を確認する**（[8.5節](../../../chapters/08-testing-and-cicd.md#85-デプロイ前チェックリストとの接続)）: マイグレーション・機能フラグ・ロールバック手順がCIの対象外であることを認識した上で、別途確認が必要な項目として提示する

## 出力フォーマット

```
## CI/CD整備状況チェック

- CI設定: あり (.github/workflows/test.yml)
- テストピラミッド: 単体42件 / 結合3件 / E2E0件 → 結合・E2Eが薄い
- Flaky testの兆候: test_send_email が3回リトライ設定 → 要調査
- CI対象外で人間が確認すべき項目: DBマイグレーションの有無、機能フラグの状態
```

## やらないこと

- CI設定ファイルの作成・変更を無断で行わない。現状の報告と改善案の提示までに留める
