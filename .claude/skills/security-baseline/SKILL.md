# security-baseline — セキュリティの基本チェック

対応章: [第7章 セキュリティ](../../../chapters/07-security.md)

## 目的

セキュリティの根っこは1つ: **外部から来たデータは、形式・内容ともに一切信用しない**（[第7章](../../../chapters/07-security.md)冒頭）。この原則が崩れている箇所を、本書で扱った代表的な脆弱性パターンに絞って検出する。網羅的な脆弱性診断ではなく、AIが書いたコードに頻出する初歩的な穴を拾うためのチェックであることに注意する。

## 使うタイミング

- 外部入力（フォーム・URLパラメータ・APIレスポンスなど）を扱うコードを書いた/レビューする時
- 「セキュリティ大丈夫？」のような曖昧な依頼を受けた時（[4.1節](../../../chapters/04-supervising-ai.md#41-良いプロンプトの作り方)の表の変換先はこのskillが担う）

## 手順

対象コードを次の観点で読む。

1. **SQL Injection**（[7.2節](../../../chapters/07-security.md#72-sql-injection)）: 文字列結合・f文字列でSQLを組み立てている箇所。プレースホルダ（パラメータ化クエリ）を使っているか確認する
2. **XSS**（[7.3節](../../../chapters/07-security.md#73-xssクロスサイトスクリプティング)）: 外部から来た値をエスケープせずHTMLに埋め込んでいる箇所。テンプレートエンジンの自動エスケープを無効化するオプション（`| safe`など）の使用箇所
3. **CSRF**（[7.4節](../../../chapters/07-security.md#74-csrfクロスサイトリクエストフォージェリ)）: 状態を変更するリクエスト（POST/PUT/DELETE）にCSRFトークンや同等の保護がないか
4. **認証・認可の漏れ**（[7.5節](../../../chapters/07-security.md#75-認証認可)）: ログインチェックのみで権限チェックがないエンドポイント、他人のリソースIDをそのまま受け取って処理している箇所
5. **秘密情報の直書き**（[7.6節](../../../chapters/07-security.md#76-秘密情報)）: APIキー・パスワード・トークンがコード中にリテラルで存在する箇所
6. **権限分離**（[7.7節](../../../chapters/07-security.md#77-権限分離)）: 1つの認証情報・プロセスに不必要に広い権限が与えられていないか

## 出力フォーマット

```
## セキュリティ基本チェック: <対象コード名>

| 種別 | 箇所 | リスク | 対策案 |
|---|---|---|---|
| SQL Injection | search() 12行目 | user_input を文字列結合でSQLに埋め込み | プレースホルダに変更 |
| 秘密情報直書き | config.py 3行目 | APIキーがリテラル | 環境変数に移動 |

問題が見つからなかった観点: XSS, CSRF
```

## やらないこと

- ここでの「問題なし」は網羅的な保証ではない。本格的なセキュリティ診断が必要な場合は専門のセキュリティレビュー（`security-review`等）や第三者診断を案内する
- 修正を無断で適用しない。対策案の提示までに留める
