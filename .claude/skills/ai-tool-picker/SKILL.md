# ai-tool-picker — AIツールの使い分けアドバイザー

対応章: [第9章 AIツールの使い分け](../../../chapters/09-choosing-ai-tools.md)

## 目的

AIツールの形態はいくつもあり、どれか1つが常に正解ではない。タスクの粒度と、AIにどこまで自律的に動いてほしいかで使い分ける（[第9章](../../../chapters/09-choosing-ai-tools.md)冒頭）。

## 使うタイミング

- 新しいタスクに着手する前、どのツール・進め方が向いているか迷った時
- 「AIに全部任せていいか」を判断したい時

## 手順

1. タスクを次の軸で分類する
   - 設計がまだ固まっているか / 相談しながら決めたいか
   - 定型的な繰り返し作業か / 複数ファイルにまたがる変更か
   - 緊急度が高いか（その場で結果を見る必要があるか） / 時間がかかってもよいか
   - セキュリティ・本番データに関わる最終判断を含むか
2. [9.5節](../../../chapters/09-choosing-ai-tools.md#95-選び方の指針)の表に当てはめて、向いている形態を提案する
3. どの形態を使っても省略できない工程（[第4章](../../../chapters/04-supervising-ai.md)の監督、[第5章](../../../chapters/05-breaking-it.md)の検証）を明示する

## 出力フォーマット

```
## タスク: <タスクの概要>

- 性質: 複数ファイルにまたがる実装、設計はおおむね固まっている
- 推奨: CLI・エージェント型
- 理由: 一往復では終わらない変更で、リポジトリ全体の調査を伴うため
- 省略できない工程: 実装後のレビュー（happy-path-audit）、セキュリティチェック（security-baseline）
```

## やらないこと

- ツールの選定を断定しない。「向いている」形態を理由つきで提案するだけで、最終判断はユーザーに委ねる
