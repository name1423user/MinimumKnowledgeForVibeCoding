# 第5章　壊す

[← 目次に戻る](../README.md)

「動く」を確認しただけでは「正しい」とは言えない（[1.3節](01-ai-writes-code.md#13-動くと正しいは違う)）。この章では、意図的にコードを壊しにいく。

## 5.1 壊し方の観点

- **境界値**: 0、負数、最大値、配列の最初と最後など、ちょうど切り替わる地点
- **異常系**: 想定していない種類の入力（数値のはずが文字列、必須項目が欠けているなど）
- **空データ**: リストが空、文字列が空、そもそもデータが存在しない
- **巨大データ**: 想定より桁違いに大きい入力やファイル
- **同時実行**: 複数のリクエストが同時に同じデータを書き換えようとする
- **ネットワーク切断**: 通信の途中で相手が応答しなくなる
- **権限不足**: 本来アクセスできないはずのユーザーがアクセスを試みる
- **データ破損**: 保存されているデータの形式が壊れている
- **再起動**: アプリやサーバーが処理の途中で再起動する
- **二重実行**: 同じ処理（決済など）が誤って2回実行される

## 5.11 壊し方をテストコードに変換する

手で壊して見つけたバグは、そのまま忘れると同じバグが後で復活する。見つけた壊し方を**テストコード**として残すことで、「二度と同じ理由では壊れない」状態を保証できる。

- **単体テスト**: 1つの関数・機能だけを狭く検証する
- **結合テスト**: 複数の部品を組み合わせた時の動作を検証する

テストの本当の目的は「バグを見つけること」より、「後で仕様を変えた時、壊れたことに気づけること」にある。テストの自動実行の仕組み自体は[第8章「テストとCI/CD」](08-testing-and-cicd.md)で扱う。

```python
# 5.1節の「境界値」「異常系」「空データ」をそのままテストケースにした例
import pytest

def test_discount_zero_percent():
    assert calculate_discount(price=1000, rate=0) == 1000

def test_discount_full_percent():
    assert calculate_discount(price=1000, rate=100) == 0

def test_discount_negative_rate_raises():
    with pytest.raises(ValueError):
        calculate_discount(price=1000, rate=-10)

def test_discount_empty_cart_returns_zero():
    assert calculate_total_discount(items=[]) == 0
```

## 演習

1. 現在触っている画面・機能を1つ選び、5.1節の観点（境界値・異常系・空データ・巨大データ・同時実行など）から最低5つ、実際に手で試して壊してみる。見つかったバグを一覧にする。
2. 演習1で見つけたバグのうち1つを選び、上のコード例のようにテストコードとして再現する。
3. 「二重実行」の観点で、自分のアプリの決済・送信・登録処理のうち1つを選び、「同じボタンを素早く2回押したらどうなるか」を実際に試す。
